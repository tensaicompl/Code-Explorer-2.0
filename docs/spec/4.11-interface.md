## 4.11.1 Stack

- `ui/`: Vite 6, React 19, TypeScript 5 (strict), deck.gl 9 with luma.gl (WebGL2, using a WebGPU device when available), `@cosmos.gl/graph` for the neighbourhood view, `@msgpack/msgpack` for tiles, Zustand for state, Radix primitives for panels, Tailwind 4.
- Explicitly not used: no ReactFlow, no ELK, no client-side community detection.
- Served by `pdx serve` (local) and `pdx server` (enterprise) from embedded assets. Both serve the same bundle.
- Auth: enterprise uses the OIDC session cookie issued by `pdx server` after the Authorization Code flow. Local `pdx serve` binds to `127.0.0.1` and requires no login.

## 4.11.2 Views

There are nine views.

| View | Purpose | Data source | Renderer |
|---|---|---|---|
| **Architecture map** (default) | System → context → service → layer → module → file → symbol with semantic zoom | hierarchy tiles (4.11.4) | deck.gl custom layers: `ContainerLayer` (rects with labels), `NodeLayer` (instanced points/icons), `AggEdgeLayer` (instanced lines), `LabelLayer` (SDF text) |
| **Neighbourhood** | Explore up to `NEIGHBOURHOOD_MAX_NODES` (20,000) nodes around a focus with GPU force layout | `GET /api/v2/neighbourhood` | cosmos.gl |
| **Dependency matrix (DSM)** | Cycles and layering at module/service/context level | `GET /api/v2/dsm` | canvas 2D (virtualised) |
| **Hotspot treemap** | Size by LOC, colour by churn × complexity or by chosen metric | `GET /api/v2/treemap` | deck.gl `ContainerLayer` |
| **Contract flow** | Services and their API/RPC/message/table links, with drill to evidence | `pdx_architecture` + `pdx_contracts` | deck.gl layered (Sugiyama layout computed server-side) |
| **Search** | FTS/semantic search, results as chips that fly-to in the map | `pdx_search` | React |
| **Findings** | Analytics findings with filters and evidence | `pdx_findings` | React table |
| **Trust & freshness** | Per-repo lag, band coverage, benchmark numbers, degraded segments | `GET /api/v2/trust` | React with small charts |
| **Chat dock** (local and enterprise, optional) | Existing concept: agent answers with evidence chips | `POST /api/v2/chat` (calls the MCP tools server-side with the configured model) | React |

All views share:

- URL-encoded state (view, manifest, focus node, zoom).
- A details panel for the selected node (symbol, evidence, callers and callees with band chips, coverage note).
- A band legend.
- A "why is this here?" drill-down that shows the L5 evidence behind any aggregated edge.

## 4.11.3 Frame budget and semantic zoom rules

Constants:

- `FRAME_BUDGET_POINTS` = 200,000
- `FRAME_BUDGET_LINES` = 300,000
- `FRAME_BUDGET_LABELS` = 2,000
- `LABEL_MIN_PX` = 14
- `FADE_BAND_PX` = 8 (the zoom range over which a level fades out while its children fade in)
- `CONTAINER_OPEN_PX` = 240

Rules:

1. The client requests tiles for containers that intersect the viewport at the depth where the container's screen size is greater than or equal to `CONTAINER_OPEN_PX` (240 px). Deeper containers are drawn as aggregates.
2. If the sum of primitives for the visible tiles exceeds a budget, the client drops tiles from the deepest level until within budget, ordering by container importance descending.
3. Edges are drawn only between visible nodes. Other edges are routed to the deepest visible ancestor pair (server-precomputed `agg_edges` per level).
4. Labels: only for containers and nodes with screen size greater than or equal to `LABEL_MIN_PX`, ranked by importance, capped at `FRAME_BUDGET_LABELS`.
5. Edge styles encode the band by colour (`precise` strongest, then `typed`, `import-guided`, `inheritance-guided`, `exact`, `scoped` progressively lighter) and the orthogonal `observed` flag by a dashed stroke. Non-drawn bands never appear as edges.
6. Ghost nodes: files with status `failed`, `partial` or `skipped` are drawn as outlined ghosts inside their folder so gaps are visible. Clicking one shows the reason.

## 4.11.4 Tiles API

`GET /api/v2/tiles/{manifest_id}/{container_id}?level={n}` returns MessagePack.

Tiles are **permission-aware**: the server filters the layout to the caller's permitted repos before serialisation (nodes, labels, aggregated edges and child containers of denied repos are removed, and containers that become empty are removed), and caches the result under the cache key `(manifest_id, container_id, level, permission_set_hash)`. The `ETag` includes the permission hash. Locally there is one permission set.

Payload shape:

```
{ container_id, level, bbox:[x,y,w,h],
  nodes:  { id:[string], kind:[u8], x:[f32], y:[f32], w:[f32], h:[f32], importance:[f32], status:[u8], label:[string] },
  edges:  { src:[string], dst:[string], weight:[u32], band:[u8] },
  children: [container_id]           // containers one level deeper, for prefetch
}
```

`kind`, `band` and `status` are `u8` codes equal to the declaration order of the corresponding enums in `kinds.rs`, `bands.rs` and `files.status` (`parsed`=0 through `redacted`=5). The codes are exported to `ui/src/consts.ts` by `scripts/consts-sync.py`.

Tiles are generated by the `layout` job (4.11.5) and cached as files under `layout/<manifest_version>/tiles/<container_id>.<level>.msgpack`. The endpoint streams the file. `ETag` = manifest version + container id. Clients cache aggressively.

## 4.11.5 Layout (server job `layout`, also run by `pdx serve` locally for one repo)

1. Build the containment hierarchy for the manifest: estate → systems → contexts → services (repos) → layer roles → modules → files → symbols.
2. For each container, compute **a squarified treemap** of its children with area = `max(1, sqrt(loc))` for files and modules, and `1` for symbols. Padding is proportional to level.
3. Inside leaf containers with 30 or more symbols, run **ForceAtlas2** with Barnes-Hut approximation (60 iterations, gravity 1.0, scaling 2.0, `linLogMode = false`) on the symbol subgraph restricted to drawn edges, then rescale into the container rect.
4. **Anchoring**: if a previous layout exists for the manifest name, initialise positions from it by `node_id`. New nodes start at their parent's centroid. The treemap for unchanged sibling sets is reused unchanged.
5. Compute `agg_edges` per level: each drawn edge is projected to the deepest ancestor pair that is visible at that level, weights are summed, and `worst_band` is kept.
6. Emit the unfiltered layout. Tiles are materialised per permission set on first request (4.11.4) and cached.

Layout is deterministic given (manifest, previous layout): random seeds are fixed, with `LAYOUT_SEED` = 42.
