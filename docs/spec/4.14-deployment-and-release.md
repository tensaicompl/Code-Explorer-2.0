# Deployment, packaging and release

> **Normative.** Changing this document requires a specification change request
> recorded in `docs/plan/ISSUES.md`, and where a stored format is affected, a bump
> of the relevant version constant.
>
> Mirrors section 4.14 of the implementation plan, which is not committed.

## 4.14.1 Artefacts

### Binary targets

`pdx` ships as static binaries for exactly these targets:

- `linux-x86_64` (musl)
- `linux-aarch64` (musl)
- `darwin-arm64`
- `darwin-x86_64`
- `windows-x86_64`

### Installation channels

`pdx` is installed through exactly these channels:

- `install.sh`
- `install.ps1`
- a Homebrew formula
- `cargo install pdx`
- `npm i -g @praxevia/pdx`, a thin wrapper that downloads the matching binary from a configurable base URL
- GitHub Releases

### Container images

The following container images are published:

- `pdx-server`
- `pdx-worker` (the same binary as `pdx-server`, with a different entrypoint)
- `pdx-zoekt`
- `pdx-precise-<lang>` (one per precise indexer language, per section 4.6.1)
- `pdx-ada-indexer`

### Helm chart

The Helm chart `deploy/helm/pdx` carries OpenShift-compatible defaults. Each default
is required:

- non-root
- arbitrary UID
- read-only root filesystem
- no privilege escalation
- `Route` and `Ingress` toggle
- PVC or S3 for segments
- external PostgreSQL supported
- `NetworkPolicy` templates

### Evaluation compose file

`deploy/compose/docker-compose.yml` is provided for evaluation.

## 4.14.2 Supply chain

Every tagged release must carry all of the following:

- SBOM: CycloneDX produced by `cargo cyclonedx`, plus `syft` for the container images.
- SLSA provenance attestation, emitted by the CI build workflow.
- cosign keyless signatures for the binaries and for the images.
- `checksums.txt`, verified by both installers.
- CodeQL for C and TypeScript.
- `cargo audit` and `cargo deny` for Rust.

Release notes list the engine version, the language matrix version and a link to the
trust page.

## 4.14.3 Versioning

`pdx` follows SemVer.

The following version constants are independent integers:

- `SEGMENT_SCHEMA_VERSION`
- `CONTROL_SCHEMA_VERSION`
- `MCP_TOOLS_VERSION`
- `TILE_FORMAT_VERSION`
- `LANGUAGE_MATRIX_VERSION`
- `ENGINE_VERSION`

The server refuses segments whose major schema differs, and re-indexes them.

## 4.14.4 Outbound network policy

The binary makes outbound connections only to the destinations listed below. The list
is exhaustive: removing a destination from it, or adding one, is a defect.

1. Configured Git hosts.
2. The configured OIDC issuer.
3. The configured segment store.
4. The configured model endpoint for the chat dock, which is off unless both
   `settings.model_provider` and `PDX_MODEL_API_KEY` are set.
5. The configured OTel collector, carrying the server's own telemetry, off by default.
6. In `pdx index --precise`, nothing: the indexers run locally.

Installers and `pdx asset install` download from the base location named by
`PDX_ASSET_BASE_URL`, at install time only.

There is no update check, and there is no usage reporting.

A unit test asserts that no other host names appear in the codebase. The provenance
scanner deny-list of Part 5.10 includes common telemetry endpoints.
