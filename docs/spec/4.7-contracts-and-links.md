## 4.7.1 Contract extraction (per repo, Stage 4)

| Contract | Provided by | Consumed by | Key normalisation | Namespace identity (required for a drawn estate link) |
|---|---|---|---|---|
| `ApiContract` | OpenAPI/Swagger files (`openapi*.{yaml,yml,json}`, `swagger*.{yaml,json}`); framework route declarations (Spring `@RequestMapping`/`@GetMapping`…, JAX-RS `@Path`, FastAPI/Flask decorators, Express/NestJS/Hono route calls, ASP.NET attributes, axum/actix routers, Go `net/http`/gin/echo) | HTTP client calls where a string literal or constant-resolved URL/path is visible (`fetch`, `axios`, `RestTemplate`, `WebClient`, `requests`, `httpx`, `HttpClient`, `reqwest`, Go `http.NewRequest`) | `METHOD + " " + path_template` with path params normalised to `{}`; host removed; trailing slash removed; lowercase method upper-cased | provider: the service authority (K8s `Service` name, Ingress/Route host, or `hostnames` declared in `pdx-arch.yaml`/`pdx.toml [identity]`); consumer: the host of the URL literal, a resolved config value, or a declared alias |
| `RpcMethod` | `.proto` service definitions | Generated-stub calls resolved by the engine to a stub class whose name matches a proto service | `package.Service/Method` | the `.proto` file shared as an `Artifact` between provider and consumer, or the same `package` declared under one `pdx-arch.yaml` context |
| `Channel` | AsyncAPI files; producer calls with a literal/constant topic (`KafkaTemplate.send`, `producer.send`, `channel.basic_publish`, NATS/Redis publish, JMS) | consumer annotations/calls (`@KafkaListener`, `consumer.subscribe`, `@RabbitListener`, `@JmsListener`) | topic/queue name; `${…}` placeholders resolved from `application*.yml/properties` when a single value exists, else key = `unresolved:<placeholder>`; `.env*` is never read (it is inside the mandatory secret-path floor, issue 38) | broker identity: bootstrap servers/cluster or namespace from config, or `brokers` declared in `pdx-arch.yaml`/`pdx.toml [identity]` |
| `Table`, `Column` | DDL files, Flyway/Liquibase migrations, ORM entity annotations (JPA `@Table`, SQLAlchemy `__tablename__`, Django `Meta.db_table`, Prisma, EF `[Table]`) | SQL string literals with `FROM|JOIN|INTO|UPDATE <table>`; ORM repository classes bound to entities | lowercase table name without schema when schema is `public`/default | datasource identity: JDBC/DSN host and database from config, or `datasources` declared in `pdx-arch.yaml`/`pdx.toml [identity]` |
| `Artifact`, `ArtifactVersion` | `pom.xml`, `build.gradle(.kts)`, `package.json`, `Cargo.toml`, `go.mod`, `*.csproj`, `pyproject.toml`, `setup.cfg`, `alire.toml`, `*.gpr` | same files' dependency sections | `ecosystem:group:name` and `ecosystem:group:name@version` | the coordinate itself (globally unique per ecosystem registry) |

Every contract row records `direction`, `owner_node_id` (the Route/Class/File node), the raw form, the normalised `key`, the `namespace_key` (identity + key) and `identity_strength ∈ {exact, declared, unresolved}` so that every estate-level edge can be drilled down to L5 evidence and its identity derivation.

### Clarifications (P2-08)

The table above is the normative target: every source it names is to be read. These
clarifications, approved with P2-08 on 2026-10-10 and in its review closure
(`docs/plan/ISSUES.md`, issues 38, 58, 59 and 62), define what the table leaves open
(identity encoding, merging) and correct it in one place, where it conflicted with the
secret floor (`.env*`, issue 38). Nothing here narrows the table. Where a source cannot
yet be proven from the facts a repository's derivation has, that is a known evidence
limitation recorded with its missing fact and owner (issues 61 and 63 to 66, tracked
source by source in issue 62), not a removal of the source.

**Placeholders and `.env` (issue 38).** `.env*` files are inside the mandatory
secret-path floor (5.12): redacted, never opened, never parsed for keys or values.
They resolve no placeholder and strengthen no identity. The configuration sources are
the repository's non-redacted `application*.yml` and `application*.properties` files,
read through the same checks as every other file, so the text read is the normalised
source. YAML mappings flatten to dotted keys (`orders: {topic: x}` is `orders.topic`),
sequences to `key[i]`; properties keep their keys. Only the simple form `${KEY}`
resolves (a default, `${KEY:x}`, does not), and only when the eligible values of `KEY`
across every such file and document are exactly one distinct non-empty value; equal
values in several files are one value, and no file, profile or order is preferred. A
value under a credential key (5.12's list: `password`, `secret`, `token`, `api_key`,
`client_secret`, `private_key` and the rest), a value a secret detector still
recognises, and a value that is itself a placeholder are never eligible. A URL may
start with `${KEY}` and go on literally; its base is then `KEY`'s value.

**Namespace keys and ids (issue 58).** A contract's id is 4.2.1's estate node id of
its kind over its `namespace_key`, nothing else: never its owner, direction, raw form,
file or line.

| Identity | `namespace_key` |
|---|---|
| `exact` or `declared` | `{"identity":"<identity>","key":"<key>"}`: compact JSON, these two members in this order, escaped as a route's qualified name (4.2.1, rule 12); the strength is not in it |
| `unresolved` | `unresolved:<repo_id>:<key>`, the registered `repo_id` |
| any, for `Artifact` and `ArtifactVersion` | the key itself; the identity is `exact` (the coordinate) |

An `exact` and a `declared` observation of one identity are one contract. A contract
with several identities (two declared host names, two literal servers, two declared
brokers) is one row per identity.

- *Strength.* `exact`: the source or configuration describing the endpoint names it
  (an absolute URL's host; a literal OpenAPI or Swagger server; a literal `AsyncAPI`
  server; a literal JDBC host and database; a literal Kafka cluster or `RabbitMQ`
  broker in the configuration, for a listener of that transport); `declared`: the
  repository's `pdx.toml [identity]` (`hostnames` for API providers, `brokers` for
  channels, `datasources` for tables and columns); `unresolved` otherwise. A
  repository's or directory's name is never an identity, and neither is a transport's
  (`kafka`, `rabbitmq`). An RPC method's namespace is not proven by a `package` alone:
  RPC contracts are `unresolved` until the link job's shared-artifact evidence (4.7.2).
- *Hosts.* Lower-cased, one terminal dot removed, user information dropped, the
  scheme's default port (`http` 80, `https` 443) omitted and any other kept, an IP
  literal as written, no DNS. A loopback or unspecified host (`localhost`,
  `127.0.0.0/8`, `::1`, `::`, `0.0.0.0`) names no service another repository could share
  and gives no `exact` identity (owner-ratified, issue 58); a local name declared in
  `pdx.toml [identity]` stays `declared`, the owner's own statement. A cluster is its hosts, each canonical, sorted, joined by `,`.
  A data source is `host[:port]/database`, credentials and properties dropped.
- *API keys.* The method upper-cased, a space, and the path: scheme, authority, user
  information, query and fragment removed; a leading `/`; every parameter, whatever
  its syntax (`{id}`, `{id:[0-9]+}`, `:id`, `<id>`, `<int:id>`), `{}`; trailing
  slashes removed except from `/`; case and percent-encoding kept; dot segments not
  resolved. A host is never in the key. An OpenAPI server's path is a prefix of every
  operation's path.
- *Channel keys.* The destination as written, case kept; a resolved placeholder its
  value; an unresolved one `unresolved:` and the placeholder as written.
- *Table and column keys.* Each part unquoted and lower-cased, `public.` dropped, any
  other schema kept; a column's key is its table's key, `.`, and the column's name
  unquoted and lower-cased.
- *Artifact keys.* `ecosystem:group:name` and `ecosystem:group:name@version`, the
  ecosystem one of `maven`, `npm`, `cargo`, `go`, `nuget`, `pypi`, `alire`, `gpr`; the
  group is the ecosystem's own (Maven's `groupId`, a scoped npm package's `@scope`) and
  empty where it has none (`cargo::serde`, `npm::lodash`; Go's name is its whole
  module path). A declared range is kept verbatim; nothing is resolved.

**Merging observations (issue 59).** Sightings of one contract in a repository merge
when their kind and `namespace_key` are equal (so are their ids), in any order:
`provides` with `consumes` is `both`, and `both` with anything `both`; the strongest
identity wins; a consumed-only sighting nominates no owner; the providers' owner is
`owner_node_id` when it is one node, and when the providers have several owners the
row has none, `props.owner_ambiguous` is `true` and `props.provider_owner_node_ids`
lists them sorted. `owner_node_id` NULL therefore means consumed-only or several
provider owners. `props.raw_forms` and `props.source_paths` are sorted sets, and so is
every other piece of evidence (`frameworks`, `route_node_ids`, `route_site_ids`,
`site_ids`, `clients`, `transports`, `placeholders`, `access_modes`); facts the key
determines (`ecosystem`, `group`, `name`, `version`; `package`, `service`, `method`)
appear once; evidence is always a sorted array with a plural name, even with one value
(owner-ratified, issue 59). Props never hold a credential, an absolute path, a whole
document or a URL's user information or query. Every row satisfies the same rules
where it is made and where it is stored (`contracts::row::check`): an artifact is
`exact` with its key as namespace; an unresolved namespace is exactly
`unresolved:<repo_id>:<key>` for the segment's repository; a resolved one is exactly the
canonical JSON above over the row's own key and a non-empty identity; the id is then the
estate id of that namespace; an ambiguous owner has no `owner_node_id` and at least two
sorted distinct provider owners that are nodes.

**The rows are the record (issue 59).** Stage 4 emits contract rows only: no contract
node in `nodes` and no `EXPOSES`, `CONSUMES`, `PUBLISHES`, `SUBSCRIBES`,
`READS_TABLE`, `WRITES_TABLE`, `DEFINES_TABLE`, `PRODUCES_ARTIFACT` or
`LINKS_ARTIFACT` edge, since 4.7.2 reads only `contracts` and the row already holds
the direction, owner and evidence. Those kinds stay in the vocabulary (4.2.4) for
views that materialise site-backed edges.

**Implementation coverage (P2-08, issue 62).** Every source is read only by its
provenance (the file imports the framework or library; a receiver's declared type,
where the facts give it) and its shape (the framework's decorator or registration, the
library's operation with the value where it takes it). A receiver's name is never
evidence, and a call resolution sends to a definition of the repository is the
repository's own. Literal and deterministic only: nothing is executed, fetched,
installed or resolved over the network, no `$ref` outside the document is followed,
and a document a parser cannot read is reported and gives no contract.

- `ApiContract` providers: OpenAPI 3 and Swagger 2 operations, owned by the document's
  file, their servers' literal authorities `exact` and prefixes part of the path; the
  `Route` nodes of Stage 4 (4.5: Spring, JAX-RS, `FastAPI`, Flask, Express), owned by
  the route and read from it, never parsed again; `NestJS` (owned by the method),
  ASP.NET attribute routing (the method) and minimal APIs, Hono, Go `net/http`, gin,
  echo, axum and actix-web (the function for its route attributes, else the file),
  without a `Route` node.
- `ApiContract` consumers: `fetch`, `axios`, `RestTemplate`, `WebClient`, `requests`,
  `httpx`, .NET `HttpClient`, `reqwest` and Go `net/http`, whose method is determined
  and whose URL is a literal, a constant the engine followed, or a leading `${KEY}`
  with one configuration value.
- `RpcMethod`: `.proto` services' methods, owned by the file; a call is a stub call
  only when resolution names its target and the target's type, less a generated
  stub's suffix, is exactly one service of the repository and its method one of that
  service's.
- `Channel`: broker client operations (`KafkaTemplate.send`; Kafka producers and
  consumers in Java, `kafka-python`, `confluent-kafka` and `kafkajs`; `pika` and
  `amqplib`; NATS; Redis publish in `redis-py`, `ioredis`, go-redis, Jedis, Lettuce and
  Spring's `RedisTemplate`; Spring's `JmsTemplate` and a JMS producer given its
  destination inline), a producer owned by its file; the engine's channel facts a
  Kafka or AMQP client call confirms in a file importing that library (issue 61);
  `@KafkaListener`, `@RabbitListener` and `@JmsListener`, consumed; `AsyncAPI` channels
  (2.x `subscribe` provides, `publish` consumes; 3.x `send` provides, `receive`
  consumes; a channel no operation uses is provided).
- `Table` and `Column`: `CREATE TABLE` in `.sql` files (not temporary ones), Liquibase
  changelogs' `createTable`, Prisma models, owned by the file; JPA `@Entity` with
  `@Table(name = …)`, Entity Framework `[Table]`, `SQLAlchemy`'s `__tablename__` and
  Django's `Meta.db_table`, owned by the class; SQL string arguments that read or write
  a table, consumed, with `props.access_modes`.
- `Artifact` and `ArtifactVersion`: `pom.xml` (the same POM's properties only),
  `build.gradle(.kts)` literals with `rootProject.name`, `package.json`, `Cargo.toml`,
  `go.mod`, `*.csproj`, `pyproject.toml` (PEP 621 and Poetry), `setup.cfg`,
  `alire.toml` and `*.gpr`; a manifest's coordinate provided by it, its dependencies
  consumed, a version emitted only when declared literally.

Known evidence limitations, each a missing fact with an owner, none a narrowing:
Kotlin calls carry no arguments (issue 63); base classes keep no type arguments, so
repositories bound to entities are not read (issue 64); a value bound before the call
(a JMS producer's destination, a router's prefix composed at run time) is not in the
facts, so such a send gives nothing and a registration on a composed router is
withheld (issue 65); deployment resources, `pdx-arch.yaml` and cross-repository
sharing are not inputs of a repository's derivation (issue 66); the engine's channel
facts carry no transport (issue 61).

## 4.7.2 Link layer (per manifest version, server job `links`)

For each contract kind, group rows across all segments in the manifest by `(kind, namespace_key)`. **A repository is a source boundary, not a service** (4.8): link endpoints are the L2 components that own the contract rows, and a link is drawn only when both sides' namespace identity is `exact` or `declared`. Estate-wide uniqueness of a bare key is never sufficient: `GET /health` exists in every service (D28).

- `ApiContract`: providers (`direction ∈ {provides, both}`) × consumers with the same `namespace_key` → `HTTP_CALLS` edges from the consumer component to the provider component, with `contract_id`. Band: `typed` when identity is `exact` on both sides and the path template matches exactly; `import-guided` when one side's identity is `declared`; `candidate` (stored in `link_meta.unmatched`, not drawn) when the consumer's authority is unresolved even if the path is estate-unique.
- `RpcMethod`: same, producing `RPC_CALLS`; band `precise` when the proto file is shared as an `Artifact` between the repos (identity `exact`), `typed` when the package is declared under one context, otherwise `candidate`.
- `Channel`: producers × consumers → `MESSAGES`; band `typed` for literal destination names with broker identity, `import-guided` with declared broker identity, `candidate` for `unresolved:` keys or unknown broker (not drawn, counted).
- `Table`: components with `WRITES_TABLE`/`READS_TABLE`/`DEFINES_TABLE` on the same `namespace_key` → `SHARES_TABLE`; band `typed` with datasource identity, `candidate` without.
- `Artifact`: `PRODUCES_ARTIFACT` × `LINKS_ARTIFACT` → `DEPENDS_ON_ARTIFACT`; band `precise` when versions match exactly, `typed` for version ranges.

Unmatched providers and consumers are written to `link_meta` as counts per kind and are visible in the coverage API. The link job reads only `contracts` tables, so it runs in seconds and is re-run on every manifest version.
